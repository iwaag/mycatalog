# カスタムノードについて

- 定義済みのカスタムノードに該当する作業がワークフローの中に含まれる場合は、必ずノード化した上で実行してほしい。ノード化すべきだったのにしなかったと気づいた場合は事後でもいいのでノードとして作業を記録してほしい。

## カスタムノード一覧

- prestudy: 文献調査作業。文献調査の指示があったときはもちろん、ある程度創造性や知識が求められる作業は可能な限り文献調査を行い、study-フォルダに有用な知識を蓄積してほしい。ただし著作権やランセンスに配慮して、特に公開する場合はなおさら。
- present: 依頼者の人間やエージェントに対して、成果のプレゼンテーションを行い、合否判定をしてもらうノード。依頼者の要望や好みの情報があればそれに可能な限り沿って実行してほしい。そういう情報が無ければ、なるべく少ない労力で成果を確認できるように臨機応変に判断してプレゼンテーションをする。明らかにプレゼンテーションが不要な場合や明確にプレゼン不要と指示があった場合以外は、ワークフローの最後にpresentノードとcleanupをセットで
- cleanup: ローカルで立ち上げたサービスの終了やレビュー用に一時起動したアプリの終了など、後始末作業全般。後始末が必要な作業でcleanupノードが存在しないのはミスの可能性が非常に高いので注意してほしい。
- boast: boast/フォルダ下に配置する、プロジェクトの実装済み機能や成果をアピールしたり、人間が成果物を使用・閲覧したりできるショーケースの役割を果たすフロントエンドを更新する作業。
- human-review: 人間によるレビューと合否判定を受けるノード。presentノードに似ているが、こちらは対象を人間に限定し、ワークフロー依頼者がエージェントの場合はそのエージェントに指示した人間もしくは指定された人間が合否判定を行う。presentationで依頼者に合否判定を受けた後で、最後にhuman-reviewを受けるという手順を推奨。

## テンプレート専用

- 以下はワークフローのテンプレートのみに用いるノード。実際に実行する予定のワークフロー、実行済みのワークフローには使わない。
- placeholder: テンプレートからインスタンス化したワークフローがplaceholderのある位置に、そのplaceholderを実行するより前の何らかのタイミングでワークフローを補完してほしいという意図を明示するためのノード。

# ノードタグについて

- webbrowser: ノードの成果物をWebブラウザから確認できる形で提示してほしい時につけるタグ
- native: ノードの成果物をPCのOSネイティブアプリとして提供して欲しい時につけるタグ
- nfs: ノードの成果物をnfs経由で授受して欲しい時に付けるタグ
- s3: ノードの成果物をs3準拠のストレージで授受して欲しい時に付けるタグ
- conditional: そのノードの実行の是非が条件次第であり、実行計画や実行直前の判断によってはスキップして良いという意図を明示する時につけるタグ
